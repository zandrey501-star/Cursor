# RAG Ассистент (Retrieval-Augmented Generation)

RAG ассистент на основе OpenAI API, ChromaDB и SQLite кеширования для ответов на вопросы на основе документов.

## 📋 Описание

Система использует технологию RAG (Retrieval-Augmented Generation) для генерации ответов на основе предоставленных документов. Процесс работы включает:

1. **Векторное хранилище** (ChromaDB) - для хранения и поиска релевантных документов
2. **OpenAI API** - для создания embeddings и генерации ответов
3. **Кеширование** (SQLite) - для оптимизации повторных запросов
4. **Оценка качества** (RAGAS) - для метрик качества системы

**Для Linux/Mac:**
```bash

./setup.sh
```

**Для Windows:**

### Ручная установка

1. **Создание виртуального окружения**

   ```bash
   # Для Windows
   py -3.11 -m venv venv_py311
   
   # Для Linux/Mac
   python3.11 -m venv venv_py311
   ```

2. **Активация виртуального окружения**

   ```bash
   # Windows (PowerShell)
   .\venv_py311\Scripts\Activate.ps1
   
   # Windows (CMD)
   .\venv_py311\Scripts\activate
   
   # Linux/Mac
   source venv_py311/bin/activate
   ```

3. **Установка зависимостей**

   ```bash
   pip install -r requirements.txt
   ```

4. **Настройка переменных окружения**

   Скопируйте файл `env.example` в `.env`:
   
   ```bash
   # Linux/Mac
   cp env.example .env
   
   # Windows
   copy env.example .env
   ```
   
   Затем отредактируйте `.env` и укажите ваш OpenAI API ключ:
   
   ```env
   OPENAI_API_KEY=your-openai-api-key-here
   ```

   Или установите переменную окружения напрямую:

   ```bash
   # Windows (PowerShell)
   $env:OPENAI_API_KEY='your-key'
   
   # Windows (CMD)
   set OPENAI_API_KEY=your-key
   
   # Linux/Mac
   export OPENAI_API_KEY='your-key'
   ```

## 🔧 Архитектура системы

### Компоненты

1. **RAGPipeline** (`rag_pipeline.py`)
   - Управляет потоком обработки запросов
   - Координирует работу векторного хранилища, кеша и LLM
   - Формирует промпты с контекстом

2. **VectorStore** (`vector_store.py`)
   - Работа с ChromaDB для векторного поиска
   - Умное разбиение текста на чанки (chunking)
   - Создание embeddings через OpenAI API

3. **RAGCache** (`cache.py`)
   - Кеширование вопросов и ответов в SQLite
   - Оптимизация повторных запросов
   - Статистика использования кеша

4. **Оценка качества** (`evaluate_ragas.py`)
   - Метрики RAGAS для оценки качества системы
   - Faithfulness и Context Precision

### Процесс обработки запроса

```
1. Пользователь задаёт вопрос
   ↓
2. Проверка кеша (если включено)
   ├─ Найдено → Возврат из кеша
   └─ Не найдено → Продолжение
   ↓
3. Поиск релевантных документов в векторном хранилище
   ↓
4. Формирование промпта с контекстом
   ↓
5. Генерация ответа через OpenAI API
   ↓
6. Сохранение в кеш
   ↓
7. Возврат ответа пользователю
```

## 📊 Оценка качества

Для оценки качества системы используется RAGAS:

```bash
cd assistant_api
python evaluate_ragas.py
```

### Метрики

- **Faithfulness** - точность ответа относительно контекста (0.0-1.0)
- **Context Precision** - качество извлечённого контекста (0.0-1.0)

## ⚙️ Конфигурация

### Параметры RAGPipeline

```python
pipeline = RAGPipeline(
    collection_name="api_rag_collection",  # Имя коллекции в ChromaDB
    cache_db_path="api_rag_cache.db",      # Путь к БД кеша
    data_file="data/docs.txt",             # Файл с документами
    model="gpt-4o-mini"                    # Модель OpenAI
)
```

### Параметры VectorStore

- `chunk_size`: размер чанка (по умолчанию 500 символов)
- `overlap`: перекрытие между чанками (по умолчанию 100 символов)
- `top_k`: количество документов для поиска (по умолчанию 3)

### Параметры генерации

- `temperature`: 0.3 (низкая для точных ответов)
- `max_tokens`: 500

## 📝 Добавление документов

Добавьте ваши документы в файл `assistant_api/data/docs.txt`. Документы должны быть разделены пустыми строками. При первом запуске система автоматически:

1. Разобьёт текст на чанки
2. Создаст embeddings через OpenAI API
3. Сохранит в векторное хранилище ChromaDB

## 🔍 Статистика системы

Команда `stats` показывает:

- Количество документов в векторном хранилище
- Статистику кеша (количество записей, размер БД)
- Используемую модель и режим работы

## 💾 Кеширование

Система автоматически кеширует ответы для оптимизации:

- Повторные запросы возвращаются мгновенно из кеша
- Экономия средств на API вызовах
- Уменьшение latency

Для очистки кеша используйте команду `clear`.

## 🐛 Решение проблем

### Ошибка: OPENAI_API_KEY не установлен

Убедитесь, что вы создали файл `.env` с вашим API ключом или установили переменную окружения.

### Ошибка при установке зависимостей

Убедитесь, что используете Python 3.11 или выше:

```bash
python --version
```

### Проблемы с ChromaDB

Если возникают проблемы с ChromaDB, удалите директорию `chroma_db` и перезапустите приложение - коллекция будет создана заново.

### Проблемы с кешем

Если кеш работает некорректно, удалите файл `api_rag_cache.db` и перезапустите приложение.
